# 提示词：构建「原则复盘系统」（Principle Retro）

> 用途：喂给任意 vibecoding 工具 / AI 编程助手，生成或迭代一个基于瑞·达利欧《原则》的个人复盘 App。
> 设计已经过一轮落地验证，以下约束请原样遵守，不要自作主张加功能。

---

## 一、目标与定位

做一个**个人高频复盘工具**，把《原则》的核心方法论落成可日常使用的系统。
- 用户已有 2.5 年日记/复盘习惯（Fiday），所以这是**自用工具**，不是给别人用的产品
- 对标《原则》方向一「个人原则引擎」的复盘核心，不碰多人协作、可信度加权、组织仪表盘
- 第一性原理：工具的成败标准是**使用频率**，不是概念多酷。所以一切设计优先"能每天/每周真的用"

## 二、技术约束（环境零摩擦）

- **单文件 `index.html`**：HTML + 内嵌 CSS + 原生 JS，**零外部依赖、零 npm、零后端**
- 数据存 `localStorage`，不联网、不传任何服务器
- 打开方式：双击 html 文件即可（用户极度反感多步安装/启动说明）
- 深色克制配色，信息密度优先，不要花哨动效

## 三、核心功能（MVP，按此五块做，不要加第 6 块）

1. **五步流程录入**
   - 字段：主题 / 目标 / 问题 / 根因 / 方案 / 执行
   - 强制按"目标→问题→根因→方案→执行"分开写，UI 上用步骤块引导，别混着填
   - 根因处提示用「5 Whys」追问到根本，不要写表面症状

2. **偏差开关 + 痛苦卡**
   - 一条「本次出现偏差」勾选框
   - 勾选后必须填写「反思」文本框才能提交，否则拦截
   - 文案点明：痛苦 + 反思 = 进步

3. **原则库**
   - 有偏差的复盘提交时，反思文本**自动沉淀为一条原则**
   - 支持手动添加原则
   - 原则可「标记失效」但**绝不物理删除**（它曾成立过，保留认知轨迹）

4. **演化树**
   - 原则按时间排成竖向时间线，视觉像 Git commit 图
   - 失效原则用灰色区分，直观看出认知迭代

5. **数据安全**
   - 一键导出 / 导入 JSON
   - 清空全部前必须二次确认（并提示先导出）

## 四、设计原则（为什么这样定，改之前先想清楚）

- **高频 > 酷**：不做 AI 自动提炼、不做多人、不做仪表盘——那些是低频/高成本，会毁掉"能坚持用"这个唯一指标
- **偏差即燃料**：没有偏差也要能记录，但偏差必须强制反思并沉淀原则，否则系统退化成普通日记
- **原则可演化**：原则库是系统的价值核心，要能随时间生长、失效、被推翻，体现"经验复利"
- **精力约束**：作者同时在求职/保研/考试/多项目并行，系统必须"打开即用、写完即走"，任何需要持续维护的机制都要砍掉

## 五、明确不做（避免精力黑洞，用熟了再叠）

- ❌ AI 自动从复盘提炼原则（先做手动+偏差自动沉淀即可）
- ❌ 可信度加权决策 / 多人投票
- ❌ 组织/人生"机器"仪表盘
- ❌ 账号体系、云同步、后端

## 六、验收标准

- 双击 html 能直接打开并正常录入
- 勾偏差不写反思 → 提交被拦
- 提交带偏差的复盘 → 原则库自动多出一条
- 演化树按时间正确展示，失效状态可切换
- 导出 JSON 后能再导入还原
