## 三、已修复的问题清单

### 1. 致命：缺少 `.dockerignore`（已修复）
- **根因**：原项目没有 `.dockerignore`。`Dockerfile.frontend` 在 `npm ci` 之后 `COPY frontend/ .`，会把**本机（Windows）的 `node_modules`**（含 esbuild 等平台原生二进制）覆盖进 Linux 镜像，导致在别的电脑 `docker compose build` 直接崩溃。后端还会把 `backend/data`（库+向量）和 `backend/.env`（密钥）打进镜像层。
- **修复**：新建根目录 `.dockerignore`，忽略 `frontend/node_modules`、`**/node_modules`、`**/__pycache__`、`backend/data`、`backend/.env`、`*.log`、`dist` 等。
- **影响**：跨平台构建不再失败，镜像更干净、更安全。

### 2. 关键：compose 密钥注入方式（已修复）
- **改动**：`docker-compose.yml` 后端 service 改用 `env_file: [backend/.env]` 注入密钥，替代原 `${DEEPSEEK_API_KEY}` 直接变量引用（后者在别处 clone 时若没设系统变量会丢 key）。
- 同时显式挂载 `./data:/app/data` 作为持久卷，db 与向量库在卷里生成，不进镜像。

### 3. CORS 来源写死（已修复）
- **文件**：`backend/app/main.py` + `backend/app/config.py`
- **原问题**：`allow_origins=["http://localhost:3000"]` 写死，换域名/端口或 Docker 部署到别的机器就要改代码。
- **修复**：`config.py` 新增 `CORS_ORIGINS`（默认 `http://localhost:3000`，可逗号分隔多个）；`main.py` 读取并解析。特别处理 `*` 通配时自动关闭 `allow_credentials`（否则 FastAPI CORS 会报错），避免"设为 * 反而崩"。

### 4. `.gitignore` 漏运行时数据（已修复）
- **原问题**：只忽略 `node_modules/ dist/ __pycache__/ .venv/ .env`，漏了 `data/`（`docker-compose.yml` 挂载的运行时库+向量），会连同 db/chroma 一起进 git / 镜像。
- **修复**：补充 `data/` 与 `backend/data`。

### 5. `start.bat` 密码误导 + 乱码（已修复）
- **原问题**：第 27 行把管理员密码写死成 `admin / 123456`，与实际 `.env` 的 `ADMIN_PASSWORD` 不符，且中文是 GBK 乱码。
- **修复**：重写为 UTF-8，密码提示改为"见 `backend/.env` 的 `ADMIN_PASSWORD`"；后端启动兼容 `backend/.venv`（有则自动 activate）。
- 注意：`start.bat` 只是**本地开发便利脚本**（非 Docker 路径）。真正"打包移植"走的是 Docker，见第四节。

### 6. 历史已修复：DashScope 批量上限（先前完成）
- `embedding_service.py` 原把整批切片一次性发给 DashScope，触发 `batch size is invalid, it should not be larger than 10`。已改为按 ≤10 分批循环，上传大文档不再失败。

## 四、部署 / 迁移到别的电脑（标准流程）

在**目标电脑**（只需装 Docker Desktop / Docker Engine）上：

```bash
# 1. 拿到代码（git clone 或拷贝整个 rag-knowledge-base 目录）
git clone <repo> rag-knowledge-base && cd rag-knowledge-base

# 2. 配置密钥：复制模板并填入你自己的 key
cp backend/.env.example backend/.env      # 若没有 .env.example，就新建 backend/.env
# backend/.env 至少包含：
#   DEEPSEEK_API_KEY=sk-xxx
#   DASHSCOPE_API_KEY=sk-xxx
#   JWT_SECRET_KEY=一段足够随机的字符串
#   ADMIN_PASSWORD=你设的管理员密码

# 3. 构建并启动（后台）
docker compose up -d --build

# 4. 访问
#   前端： http://<目标机IP>:3000
#   API：  http://<目标机IP>:8000/docs
```

**要点**：
- 无需安装 Python / Node / Chrome / 数据库 —— 全在镜像里，靠 `.dockerignore` 保证镜像干净。
- 数据持久化在挂载卷 `./data`，换机器时连同 `data/` 一起拷走即可保留知识库。
- 若前端要跑在别的域名/端口，在 `backend/.env` 加一行 `CORS_ORIGINS=https://你的域名`，无需改代码。

## 五、代码可读性与工程性评估

**优点**
- 分层清晰：`api/`（路由）、`services/`（业务）、`schemas/`（模型）、`middleware/`、`database` 各司其职。
- `config.py` 用 pydantic-settings + 强制读取 `.env` + 类型强转，防系统环境变量污染，工程上很稳。
- 文档齐全：`docs/使用说明.md` 覆盖双角色、知识库管理、问答、看板、接口速查、FAQ。

- `nginx.conf` 的 `server_name localhost` 在单 server 块下不影响按 IP 访问，若上生产域名可改成对应域名。
